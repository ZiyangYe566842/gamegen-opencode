# CLI guide

Run from the repository root using `node bin/gamegen.mjs`. The installer also exposes `gamegen` if its bin directory is on PATH.

| Command | Purpose |
| --- | --- |
| `demo [--no-install]` | Copy the starter game and local assets; no model requests |
| `create "<prompt>"` | Generate a game through OpenCode |
| `improve "<feedback>"` | Improve the selected game |
| `list` / `use <job_id>` | List jobs or select the current job |
| `where` | Print the selected project directory |
| `qa` | Build, test, and produce quality reports |
| `preview` | Start the Vite development server |
| `export` | Write `export.zip` beside the selected project |
| `doctor` / `auth-check` | Check tools/files or provider configuration |
| `render-config [--profile <name>]` | Render the OpenCode configuration |
| `profile show` / `profile set <name>` | Inspect or update the active profile |

## Project selection

`improve`, `qa`, `preview`, `where`, and `export` accept either `--job <job_id>` or `--project <path>`. With neither, they select `generated/latest`. Job IDs are generated by this CLI; use an ID printed by `list`.

## Generation options

| Option | Meaning |
| --- | --- |
| `--type`, `--title`, `--style` | Prompt/spec metadata |
| `--image <path>` / `--video <path>` | Repeatable references |
| `--image-role role=path` / `--video-role role=path` | Repeatable references with explicit roles |
| `--max-video-frames 8` | Frame attachment limit per video |
| `--use-openai-images` | Explicitly request paid image assets |
| `--profile <name>` | Profile override for this operation |
| `--max-rounds 3` | Outer QA/repair round budget |
| `--visual-rounds 2` | Visual polish budget |
| `--min-visual-score 4` | Heuristic visual-score requirement |
| `--max-images 12` | Spec-level image budget hint |

The image budget is recorded in the game spec; it is not an enforced billing cap. Improvement uses a default repair budget of 2. `--rounds` remains a legacy alias in the argument schema; prefer `--max-rounds`.

Profiles: `free`, `cheap`, `balanced`, `deep`, `experimental`. All provider/model identifiers must match the model catalog available to your authenticated OpenCode instance. Experimental entries require replacement before use.

## Reports and export

Reports include `game_spec.json`, `asset_manifest.json`, `qa_report.json`, `asset_validation_report.json`, `iteration_report.json`, and heuristic visual/feedback reports.

Source export includes source, package metadata, and project reports. It omits dependency/build directories, environment files and backups, Git history, raw uploads, reference analysis, and local agent configuration. Review any additional files produced by agents before sharing the archive.

The starter has one template. Creating a different game type relies on the generation agent changing the template code.
